# Conversation Quality Analytics (CQA) — Freedom Broker

Система автоматической оценки качества диалогов (текстовых чатов и аудиозвонков) операторов поддержки Freedom Broker по официальному чек-листу C01–C08.

---

### Что это и что умеет

- **8 критериев чек-листа C01–C08**:
  - C01–C02 «Начало и понимание запроса»
  - C03–C04 «Безопасность и решение»
  - C05–C07 «Ведение и завершение диалога»
  - C08 «Грубые нарушения»
- **Поддержка N/A с перераспределением веса**: N/A разрешён для C02, C03, C04 и C07; запрещён для C01, C05, C06, C08. Если критерий неприменим, его вес исключается, а оставшиеся веса пропорционально масштабируются до суммы 100%. Итог округляется `HALF_UP` до 2 знаков.
- **C08 отдельным флагом**: критическое нарушение фиксируется как отдельный флаг; оно не обнуляет и не уменьшает математический балл диалога.
- **Доказательства с переходом к реплике**: цитаты модели привязаны к индексу реплики (`message_index`). В интерфейсе клик по цитате подсвечивает точную строку в транскрипте, а для аудиозвонков — перематывает плеер к приблизительному моменту реплики.
- **Апелляции и пересчёт**: пользователь с ролью «Аналитик» может оспорить любой критерий с комментарием (кнопка «Оспорить»). Пользователь с ролью «Проверяющий» подтверждает или изменяет оценку (кнопки «Подтвердить» или «Изменить» с выбором нового ответа и причины); изменённая оценка детерминированно пересчитывает итоговый балл по той версии чек-листа, в которой проводилась оценка (с сохранением базового балла).
- **Пакетная оценка**: запуск очереди диалогов с настраиваемой параллельностью (1–4), автоматическими повторами transient-ошибок (до 3 попыток), защитой от дублирования затрат (повторный запуск оценивает только диалоги без успешной оценки), лимитом расходов в USD (`costCap`) и мгновенной остановкой при фатальных ошибках (`no_api_key`, `auth`, `model_not_found`).
- **Бенчмарк**: экран «Чек-лист» сравнивает результаты AI и эвристики на 34 размеченных учебных диалогах (`study`) с расчётом метрик MAE, точности по критериям, матриц шкальных оценок и F1 для флага C08.
- **Смена критерия через интерфейс**: пользователь с ролью «Настройщик» может редактировать формулировку, шкалу или вес критерия прямо в UI. При сохранении создаётся новая версия чек-листа с id вида `checklist-vN-<hash>`, а старые оценки остаются неизменно привязаны к архивной версии.

### Быстрый старт

Требования: **Node.js 22.9+**, npm.

```bash
# 1. Установка зависимостей
npm install

# 2. Настройка окружения (при необходимости)
cp .env.example .env

# 3. Запуск сервера разработки
npm run dev
```

Приложение открывается в браузере по адресу: **`http://localhost:8080/`** (или `http://127.0.0.1:8080/`).

### Локальная модель через Ollama / LM Studio

CQA поддерживает работу с локальными моделями без отправки данных во внешние API:

1. Запустите Ollama и загрузите модель, например:
   ```bash
   ollama run qwen2.5:14b
   ```
2. Задайте переменные в `.env`:
   ```env
   LLM_BASE_URL=http://localhost:11434/v1
   LLM_MODEL=qwen2.5:14b
   ```
3. При старте приложение определит `isLocal = true`:
   - Ключ API не требуется.
   - Таймаут запроса автоматически увеличивается до 180 секунд (`180000` мс).
   - Расчётная стоимость диалогов обнуляется (`$0.00`).
   - В интерфейсе отобразится бейдж: `локальная: localhost`.

### Сравнение моделей

CQA позволяет сравнивать качество работы разных моделей (облачных, локальных и агрегаторов вроде OpenRouter) на одном и том же наборе диалогов.

#### Пример `.env` для Gemini API напрямую:
```env
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai
LLM_API_KEY=<ключ из Google AI Studio>
LLM_MODEL=gemini-3.8-flash
LLM_REASONING_EFFORT=low
LLM_TIMEOUT_MS=120000
```
> **Примечание к Gemini**: имя модели сверить со списком моделей Google (`gemini-3.8-flash` или новее). Если модель думает долго — увеличивайте `LLM_TIMEOUT_MS` или устанавливайте `LLM_REASONING_EFFORT=low` или `none`.

#### Пример `.env` для OpenRouter (бесплатные или сторонние модели):
```env
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=<ключ>
LLM_MODEL=<id модели>
LLM_PRICE_INPUT_PER_M=0
LLM_PRICE_OUTPUT_PER_M=0
LLM_TIMEOUT_MS=300000
```

> **Переключение на лету**: прямо в интерфейсе (поле «Модель» в панели фильтров) можно менять модель на лету — например, переключать различные модели OpenRouter без перезапуска сервера.
>
> **Оценка стоимости**: если тарифы не заданы через переменные `LLM_PRICE_INPUT_PER_M` и `LLM_PRICE_OUTPUT_PER_M`, калькулятор использует базовые тарифы Grok 4.5 ($2/$6 за 1M токенов) как безопасную оценку сверху для более дешёвых моделей.

#### Процедура сравнения:
1. Нажмите **«Учебные, 34»** в интерфейсе для загрузки эталонного набора диалогов (RU, KZ, EN).
2. Запустите пакетную оценку на **модели A** (кнопка «AI по списку»). Дождитесь завершения.
3. Смените переменные `LLM_MODEL` (и при необходимости `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_PRICE_*`) в `.env` и перезапустите dev-сервер: `npm run dev` (или укажите модель прямо в поле «Модель» в UI).
4. Запустите пакетную оценку на **модели B**.
5. Перейдите на экран **«Чек-лист»** и сравните метрики моделей: распределение баллов, согласованность с AI Judge, частоту флагов C08 и долю диалогов в статусе `needs_review`.

> [!WARNING]
> Бесплатные и скрытые (stealth) модели у публичных провайдеров могут хранить запросы и ответы у провайдера — условия смотрите на странице модели, иметь жёсткие лимиты запросов (rate limits) и внезапно удаляться из каталога без предупреждения. Реальные клиентские звонки и конфиденциальные данные отправлять в такие сервисы допустимо только с явного разрешения службы информационной безопасности.

### Как устроена оценка (Архитектура пайплайна)

1. **Один вызов по всем 8 критериям**: Модель получает полный транскрипт и актуальные тексты рубрик текущей версии чек-листа. Возвращает структурированный JSON с ответами, цитатами (`quote`), индексами (`message_index`), проверенными диапазонами (`checked_range`) и обоснованиями (`reason`, `na_reason`).
2. **Техническая проверка цитат (`assemble`)**:
   - Каждая цитата сверяется на точное совпадение подстроки с репликой транскрипта по `message_index`.
   - Проверяется допустимый автор реплики (`evidenceSpeakers`): реплика клиента (`client`) никогда не может подтверждать действие или нарушение оператора.
   - Для ответов «НЕТ» проверяется интервал ожидания (`checked_range`).
3. **AI Judge**:
   - Отдельный системный вызов независимого судьи.
   - Судья оценивает соответствие ответов и цитат рубрике чек-листа (`valid`, `invalid`, `needs_review`).
   - Для длинных диалогов контекст подаётся скользящими окнами (`JUDGE_WINDOW = 16`) с сохранением исходных индексов и концовки диалога.
4. **Точечный повтор спорных критериев**:
   - Если критерии признаны судьёй спорными (`invalid`, `needs_review`) или не прошли техническую проверку, формируется точечный повторный запрос только по этим критериям с передачей замечаний.
   - Успешно исправленные критерии подменяются; если повтор не помог, сохраняются исходные данные с пометкой `needs_review`.
5. **Детерминированный расчёт балла**:
   - Модель **никогда не считает итоговый балл**.
   - Балл вычисляется строго математической функцией на сервере (`computeScore`) с правилом `HALF_UP` и перераспределением весов N/A.

### Проверки и тестирование

Команды верификации качества проекта:
```bash
npm run test:cqa      # Запуск тестов CQA
```

> **Важное предупреждение о `npm test`**:
> Базовая команда `npm test` в шаблоне окружения запускает тесты шаблона `scripts/brand-check/*.test.mjs`, которые требуют каталог `.grok/`. При его отсутствии тесты шаблона падают (8 failure). К логике и коду CQA это не имеет отношения.
> Для проверки CQA запускайте: **`npm run test:cqa`** (все тесты проходят успешно: pass, 0 fail).

### Сценарий защиты на 5 минут (по шагам гайда организаторов)

1. **Интерфейс и выбор диалога (1 минута)**:
   - Откройте вкладку «Диалоги».
   - Нажмите кнопку «Демо, 14» (или «Учебные, 34»).
   - Продемонстрируйте фильтрацию по каналу («чат», «звонок») и языку (RU, KZ, EN).
   - Выберите диалог `p1-ru-001` (или звонок `p1-ru-007` с аудиоплеером).
2. **Оценка, обоснование, цитаты и N/A (1.5 минуты)**:
   - В карточке диалога нажмите кнопку «Оценить AI» (также покажите кнопки «Эвристика» и «Ручная разметка»).
   - Обратите внимание на обоснование модели (`reason`) под каждым критерием.
   - **Переход к реплике**: кликните по цитате критерия C01 — транскрипт автоматически прокрутится и подсветит реплику оператора с представлением.
   - **Пример N/A**: покажите диалог `p1-ru-002` (общий вопрос о пополнении счёта без запроса персональных данных и защищённых действий) — в C03 выставляется N/A, вес 20% перераспределён, итоговый балл рассчитан корректно из оставшихся критериев.
   - **Флаг C08**: покажите диалог `p1-ru-004` (предложение перевода на Kaspi в обход кассы) — выставлен флаг грубой ошибки, но балл по остальным критериям сохранён.
3. **Апелляция и пересчёт балла (1 минута)**:
   - Выберите в шапке роль «Аналитик».
   - В карточке диалога у нужного критерия (например, C01) введите комментарий в поле «Почему оценка спорна» и нажмите кнопку «Оспорить».
   - Переключитесь на роль «Проверяющий», найдите поданную апелляцию.
   - Нажмите «Подтвердить» (если согласны с моделью) или выберите новый ответ, укажите причину решения и нажмите «Изменить».
   - Покажите, как при изменении ответа пересчитался итоговый балл диалога, при этом первоначальная оценка модели зафиксирована в истории.
4. **Изменение чек-листа и версионирование (1.5 минуты)**:
   - Переключитесь на роль «Настройщик» и откройте вкладку «Чек-лист».
   - Отредактируйте текст рубрики или вес критерия (например, в C01).
   - Нажмите кнопку сохранения — появится новая версия чек-листа с идентификатором вида `checklist-vN-<hash>`.
   - Вернитесь к диалогам и запустите оценку: новая оценка пойдёт по актуальной версии чек-листа, а предыдущие оценки сохранят связь с официальной версией `official-chat-v1`.

### Ограничения и допущения

1. **Реальный API организаторов**: Внешний эндпоинт организаторов с рабочим ключом в данной среде не проверялся вживую. Интеграция реализована по контракту ТЗ и покрыта автоматическими тестами на мок-ответах.
2. **Аудиозвонки**: Для звонков применяется чатовый чек-лист C01–C08 (адаптация согласно ТЗ, отдельная голосовая рубрика организаторами не публиковалась).
3. **Таймкоды звонков**: Привязка к фрагменту аудиозаписи выполняется приблизительно, от времени первой реплики с корректной ISO-меткой.
4. **Хранение данных**: Состояние диалогов, оценок, версий чек-листов и решений апелляций сохраняется в `localStorage` браузера пользователя. Это исключает передачу чувствительных транскриптов во внешние базы данных.
5. **Бенчмарк**: Набор из 34 учебных диалогов (`STUDY`) размечен авторами проекта для калибровки и локального регрессионного тестирования, он не является скрытым эталоном организаторов.
